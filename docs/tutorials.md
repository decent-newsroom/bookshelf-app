# Adding tutorial content

The Tutorials feature supplies a local catalog and a reusable viewer. Its two stable topics are **Getting started** and **Tracking progress**. They are intentionally empty until the user provides and reviews their content. Do not add tutorial prose, sample lesson text, or a proposed topic outline as part of implementation work.

The catalog API is in `ui/tutorials/TutorialCatalog.kt`. `TutorialTopic` owns each stable ID and its `titleRes` and `summaryRes`; retain those IDs (`getting_started` and `tracking_progress`) when supplying reviewed copy. Add localized topic title/summary strings and each step's title/body strings to `res/values/tutorial_strings.xml` (and corresponding locale resource files where available). Then replace the empty step list for that topic in `TutorialCatalog` with its ordered `TutorialStep` entries. Give each step a stable, topic-local `id` and point `titleRes` and `bodyRes` at the approved strings. `TutorialStep.illustrationRes` is optional and accepts a local drawable; when used, set `descriptionRes` to a localized, meaningful alt-text string. Leave both fields null when the step has no illustration.

The viewer owns paging, scroll restoration, navigation, and exit behavior. A content update should supply only the reviewed topic and step resources and their catalog references; it should not add tutorial-specific persistence, remote loading, or reading actions. Keep the full tracking explanations in place while the Tracking progress topic has no steps. Once that topic has approved steps, the existing UI can select its concise presentation. Status, errors, and privacy confirmations remain visible regardless of tutorial content.

Before release, confirm that both topics have user-supplied, reviewed content, all referenced resource IDs resolve, localized text is present, and any image alt text describes its image. Verify the rendered steps at large font sizes and with accessibility services. Follow the manual checks in [ADR 0049](decisions/0049-topic-tutorials.md); Gradle verification and device checks are performed by the user per AGENTS.md.
